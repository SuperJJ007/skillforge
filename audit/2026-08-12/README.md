# SciForge 首页简化审查

## 审查范围

- 页面：`skillforge/src` 当前 SciForge 首页。
- 用户目标：尽快把一个科研任务转成可验证、可使用的 Agent 工具或工具链。
- 本轮用临时依赖环境渲染源码；项目内 `dist/` 是过期的 Math GPS 构建，不作为证据。

## 结论

复杂感主要来自“同时讲六件事”，不是单纯的配色或留白问题。首页需要从营销陈列页收敛成一条任务路径：

> 描述科研任务或直接搜索 -> 获得少量匹配结果 -> 用评测证据做决定。

## 步骤与健康度

### 1. 首次进入首页 — 需要明显精简

首屏同时出现 7 个中部导航入口、3 个右侧操作、上线徽章、品牌大标题、价值说明、搜索、4 个类型筛选、5 个热门标签和 4 个统计指标。用户还没行动，就要先理解多套产品概念。

建议：导航只保留“发现工具、任务规划、评测”和一个主操作；Hero 只保留一句结果导向定位、一个输入框和一个次级入口。

### 2. 搜索“单细胞” — 核心功能可用，但结果模式不够聚焦

搜索能快速返回一个相关工具，这是当前页面最清晰的价值。但结果只是插入在首页上部，下面的统计、评测、模拟器、学科和套装仍全部保留，用户没有进入一个专注的“找工具”状态。

建议：输入后切换为独立结果模式，隐藏首页营销板块；只保留结果数、类型筛选、排序和结果卡。

### 3. 390px 移动端 — 有明显布局故障

实测视口宽 390px，但页面 `scrollWidth` 为 602px，产生横向溢出。四列统计和三列评测卡仍保持多列布局；主导航在 900px 以下直接消失，只剩“提交作品”和“登录”，没有移动端菜单。

建议：统计改成 2x2，评测卡改单列，并提供可点击、可键盘操作的移动菜单。

## 最优先的五个改动

1. 确立唯一主任务：主入口建议改成“描述你的科研任务”，直接连到现有任务规划器；“直接搜索工具”作为次级入口。
2. 缩减导航：保留“发现工具 / 任务规划 / 评测”；Docs、About、Hub、提交作品移入页脚或账户菜单。
3. 删除首页重复证明：上线徽章和四格统计条至少删除一组；评测区只留一条可信度摘要和一个精选案例。
4. 把“智能 Agent 场景推演”移到评测中心，把“推荐科研 Agent 套装”移到任务规划器结果或学科页。
5. 搜索采用渐进披露：空状态只显示输入框和最多 3 个示例；输入后才显示类型筛选，并进入专注结果页。

## 建议的信息结构

1. 精简导航
2. 一句价值主张 + 任务输入框
3. 3 个匹配工具或管线
4. 一条评测证据摘要
5. 3 个学科入口
6. 页脚

## 可信度与可访问性风险

- 页面声称收录 `1,420+`，但当前静态数据 `getAllTools()` 只返回 11 个工具；上线前应改为真实数据驱动或明确展示口径。
- 导航下拉仅靠 hover 打开，缺少键盘和触屏展开状态。
- 搜索框只有 placeholder；筛选按钮没有可感知的选中状态；视觉上的 `⌘ K` 暂无对应快捷键逻辑。
- 部分浅灰、浅绿小字对比度偏低；完整 WCAG 结论仍需键盘、读屏和缩放测试。
