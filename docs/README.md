# SkillForge 文档

本目录只保留长期维护且可追溯的文档；每类事实只在一个位置拥有权威。

| 类别 | 文档 | 状态 | 唯一职责 |
| --- | --- | --- | --- |
| 产品权威 | [产品权威](authority/product.md) | 产品基线，实施待办 | 产品边界、数据所有权与已确定/待确认的产品决策 |
| 系统架构 | [系统架构](architecture/system.md) | 架构基线，尚未实现 | 系统形态、分类模型、数据模型、API、实施顺序与验收；[6.0 节](architecture/system.md#60-计数器与版本术语)统一 revision/generation/epoch 术语 |
| 架构子系统 | [GitHub 同步实现规范](architecture/github-sync.md) | 首版规范，尚未实现 | 仓库解析、快照、Webhook、队列、额度、Worker、撤权与保留策略；该子系统的唯一实现规范 |
| 代码接口 | [接口目录](interfaces/README.md) | 已索引进程内边界；尚无 HTTP 合同 | 已实现的跨模块、跨进程或对外调用边界 |

文档中的“已存在”描述当前代码；“目标”“建议”“默认方案”均表示后续实现设计，不能当作已经上线的能力。

阅读顺序：先读产品权威，再读系统架构；实现 GitHub 子系统时转到 GitHub 同步规范取得列级 schema、状态机和事务参数；需要稳定接口时查接口目录。

`.work/plans/` 与 `.work/handoffs/` 只用于本地临时计划和交接，已由 Git 忽略，不能作为权威依据或替代上述文档。长期结论应提炼到对应的权威文档。

冲突处理：当前代码与测试决定“已实现了什么”；产品权威决定“产品允许什么”；架构文档只描述尚待实现的目标设计；接口文档必须跟随已实现代码。GitHub 子系统的列级 schema、状态机和运行参数以同步规范为准，但不得覆盖产品权威。出现冲突或 API/验收项无法对应数据模型时，必须先修正相应文档，不得由实现者自行择一、新建隐式表或在 JSON 中补状态。
